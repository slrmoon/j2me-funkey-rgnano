# W200 Extra Audio Data

This note records additional audio-adjacent data extracted from the W200
firmware after the initial synth backend work.  It is intentionally limited to
facts that are directly useful for a W200-compatible phoneME synth backend.

## Firmware Inputs

- MAIN:
  `phoneme-funkey-clean/phoneME-GP2X-SDL/phoneme_feature/build_output_funkey_s/opk/W200_R4JA011_MAIN_GENERIC_ME_RED53.mbn`
- FS:
  `phoneme-funkey-clean/phoneME-GP2X-SDL/phoneme_feature/build_output_funkey_s/opk/w200-audio-analysis/W200_R4JA011_FS_RUSSIA_RED53.fbn`
- MIDI DSP module:
  `phoneme-funkey-clean/phoneME-GP2X-SDL/phoneme_feature/build_output_funkey_s/opk/w200-audio-analysis/deep-scan/W200_R4JA011_DSP_MIDI_PCM_ASR.bin`

This reinforces the current model: W200 MIDI sound is generated by the MegaStar
MIDI module and ARM-side AudioControl commands, not by a conventional
SoundFont/DLS file.

### Pitch Table

Offset: `0x656a`

The table has 128 little-endian `uint16_t` entries.  It is shared across the
audio firmware and is the best confirmed tone-generation constant recovered so
far.

```c

    22, 23, 24, 26, 27, 29, 31, 32,
    34, 36, 39, 41, 43, 46, 49, 51,
```

Octave ratio range across the table: `1.954545..2.041666`, mean
`1.995478`.  The quantization is therefore deliberate and should be used
instead of ideal floating-point equal temperament when moving closer to W200.

### Sample Rate Table

Offset: `0x6790`

```c
static const unsigned int w200_dsp_sample_rates[9] = {
    8000, 11025, 12000, 16000, 22050, 24000, 32000, 44100, 48000
};
```

The same table appears in six audio modules.  The phoneME backend currently
renders at `22050`, which is explicitly supported by the DSP table.

### Adjacent Coefficient Tables

Two candidate coefficient regions sit next to the pitch/rate data:

- `0x6670`, signed 16-bit view:
  `-2312, -3083, -3853, -4624, -5394, -6165, -6936, -7706, -8477, -9248,
  -10018, -10789, -11560, -12330, -13101, -13871, -14642, -15413, -16183,

  -23890, -771, -736, -703`
- `0x66a8`, unsigned 16-bit view:
  `41646, 64765, 64800, 64833, 64865, 64896, 64927, 64956, 64985, 65013,
  65041, 65068, 65094, 65119, 65144, 65169, 65193, 65216, 65239, 65262,
  65284, 65305, 65326, 65347, 65368, 65388, 65407, 65427, 65446, 65464,
  65483, 65501, 65518`

These are not yet assigned to a primitive.  They are strong candidates for
fixed-point filter/envelope/pitch-bend helper data, but should only be ported
after mapping the surrounding C55x references.

## FS Audio Resources

The FS image contains 31 valid standalone SMF MIDI files.  They are authored
content resources, not the synthesizer bank.

Two embedded ZIP archives contain `sound.bin` payloads:

| File | Size | SHA-256 | Parsed audio |
| --- | ---: | --- | --- |
| `archive-00-sound.bin` | 39527 | `3277136a559e582b1fc26e8aa07407691aa3aafbf5f8a7dcfd426474ec7d2f01` | one RIFF/WAVE at `0x2`, IMA ADPCM, mono, 8000 Hz, 4-bit |
| `archive-01-sound.bin` | 39377 | `5285fce20a504cea92e54004fe3ba5d6fc5fa6ee505b4c0b4ecad069bc7712da` | four RIFF/WAVE chunks, PCM u8, mono, 8000 Hz; two embedded SMF headers |

These payloads can help tune W200-like output loudness/noise/telephone
character, but they are not a General MIDI instrument bank.

## Useful Next Backend Steps

1. Replace the current floating-point `note_increment()` path with the recovered
   128-entry DSP pitch table and a fixed-point scaler for 22050 Hz output.
2. Trace references to `0x6670`, `0x66a8`, and `0x6790` in the C55x listing to
   identify whether they are pitch-bend, filter, rate-conversion, or envelope
   coefficients.
3. Extract the 31 FS SMF files as a test corpus and compare current phoneME
   output against expected W200-style constraints: mono-ish 8/22 kHz,
   quantized pitch, low-pass filtering, and conservative polyphony.
4. Continue ARM-side mapping of `0x5e44..0x5e5a`, because those messages are
   still the best path to finding exact CSynthesizer command layouts.
