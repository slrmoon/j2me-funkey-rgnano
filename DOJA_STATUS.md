## Sound (2026-10-22, in progress)
- Reference: Keitai Wiki MLD sequencer + Yamaha MA-3 FM synth (Guy Perfect, public domain; MA3Sampler MPL-2.0, maintained in SquirrelJME `modules/vendor-api-keitaiwiki-music`, voice/wave ROM data from the same module). `tools/doja/mldref/build.sh` builds it on a desktop JDK 21; `Render.java` renders MLD → WAV.
- C port: `fkaudio/fka_mld.c` + `fka_mld.h` + `fka_ma3_rom.h` (generated by `tools/doja/mkma3rom.py`). Compile with `-ffp-contract=off -fwrapv`. All 44 MLDs of Rockman Puzzle Battle render **bit-identical** to the reference on x86 (`tools/doja/mldref/render.c` + `cmp.py`).
- ARM: the FunKey SDK musl `floor()` is broken (returns x for |x| >= 1; the rounding trick was optimised away when musl was built), libm is not used by the synth: fdlibm log/pow ported in `fka_mld.c`, tables from `fka_ma3_tables.h` (generated by `tools/doja/mldref/gentab.c` with -DFKA_MLD_GENTABLES). All 44 files bit-identical under qemu-arm too. Speed: qemu renders 46 s of music in ~11 s.
- Integrated: `fka_decode` detects `melo` → FKA_KIND_PCM "audio/x-mld", streamed by the MA-3 synth (window like MP3, rewind = reset + re-render), mono = (L+R)/2. Host test of the whole engine (`tools/doja/mldref/eng.c`, EAS stubbed): output == reference mono, corr 0.99999997, gain 1.0.
- AudioPresenter plays MLD natively ("audio/x-mld"; MIDI conversion only as fallback); DoJa SET_VOLUME mapped as linear gain (MMAPI level = sqrt). CHANGE_TEMPO / TRANSPOSE_KEY are logged as unimplemented.
- Still to do: tempo/transpose attributes, MLD ADPCM resources (5 of Rockman's 44 MLDs have voice samples; openDoJa's MA-3 path skips them too, only its FueTrek engine plays them).

## Sound accuracy and speed (2026-10-22, round 2)
- The SquirrelJME copy we matched first has known bugs that openDoJa (GrenderG) fixed; the C port now follows openDoJa's MA-3 path and is **bit-identical to it** for all 44 Rockman MLDs, plain and looped, x86 and ARM (`tools/doja/mldref/build-opendoja.sh`, `ORender`, `cmp-od.py`; `TRender` + `tcmp.sh` compare sampler call traces). openDoJa is GPLv3 and only used as a test oracle; the behaviour was reimplemented. Fixes:
  - banks 0/1 keep the program number (every melody part used preset 0 — the main reason the music sounded wrong);
  - extended wait 0xDC (high byte of the next delta: timing), track control 0xDD (repeat sections);
  - playback starts at the `cuep` offset (the intro before cuepoint-start is played), cuepoint loops jump in place with notes ringing through, release tails after the last event (4 s cap);
  - vibrato for EVB operators, master tune applied in note bends, master volume curve (x/127), no master pan/tune products in panpot/bend, wave-channel volume/pan events;
  - resource (0x7F) events skipped with the right body length (`exst` count).
- Endless BGM (track-control repeat forever): the duration scan stops at 10 min and reports unknown length (it used to block the VM when the song started).
- AudioPresenter posts AUDIO_LOOPED (not AUDIO_COMPLETE) on loops.
- Second launch black screen: the game loads ~600 images with lock/unlock + System.gc() per image. Fixed by (1) unlock/present no longer waiting for the display — frame copied to a front buffer, a Java presenter thread shows it at <= 30 fps (the native limiter sleeps with all Java threads stopped); (2) System.gc() does at most one full GC per second, young GCs in between. Loading in qemu: 15 s -> 4 s to the CAPCOM logo; the "game data / sound data" progress bars now show.
- JIT thrash: the game's 5 KB main loop failed its OSR compile (out_of_memory) and was recompiled every few ms: 25-50% CPU in the JIT. Now retried with a bigger buffer, given up after 5 failures (`PHONEME_TRACE_COMPILE=1` logs compilations).
- Scratchpad streams buffered (DataInputStream read byte per native call, a commit per written byte); media reads stop at the format end.
- Diagnostics: `-Ddoja.stats=1` (frames/s), `-Ddoja.trace=1` (also jar entries, image decode times), `PHONEME_PROFILE=1`.
- Open: the game's main loop now runs interpreted (its OSR compile still fails, reason not found yet); MA-3 synth CPU on the device unmeasured (x86: 2-10% of a core per song).
